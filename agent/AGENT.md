# Curriculum Agent — Daily Concept Deep-Dive

This document is the prompt + operating manual for the daily NextOps Curriculum Agent. The agent fires every weekday morning via a Claude Code remote routine. It is autonomous between fires.

## Mission

Build, maintain, and refine the NextOps Curriculum (this repo) one concept per day. The output is markdown deep-dives under `curriculum/concepts/` plus a GitHub issue per fire for human review.

## Each fire — what the agent does (in order)

### Step 1 — Pick a concept

Read `curriculum/00-overview.md` and the existing files under `curriculum/concepts/`. Identify either:
- A concept from the eight pillars that hasn't been deep-dived yet (priority).
- A concept that was deep-dived but is older than 90 days and may need a refresh based on newer business-thinking literature.
- A concept the human flagged in a previous issue with `revisit-needed`.

If multiple candidates, pick the one most upstream (foundational concepts before advanced ones).

### Step 2 — Research

Use WebSearch to find:
- The 2-3 most authoritative current sources on the concept (textbooks, founder essays, recent VC blog posts, academic papers — be biased toward operator-written content over academic).
- Specific real-world examples that would resonate with an SA / pan-African audience.
- Failure cases — companies that got this concept wrong and what happened.

If WebSearch is unavailable, use in-distribution knowledge but flag the deep-dive as `unverified-citations` in the front matter.

### Step 3 — Write the deep-dive

Create `curriculum/concepts/{concept-slug}.md` with this structure:

```markdown
---
concept: {full concept name}
pillar: {1-8 from the eight pillars}
status: draft
created: {ISO date}
agent_run_id: {unique id from the agent run}
sources_verified: yes|no
---

# {Concept name}

## What it is (90-second version)
[Plain-English explanation a smart 14-year-old can follow.]

## Why it matters
[The actual stakes. What goes wrong without it.]

## Real-world examples
[At least 3 concrete examples. Bias toward SA / African examples where possible.]
[Include at least 1 failure case showing the cost of getting it wrong.]

## In-game expression — Founder Mode mapping
[Specific NPC interaction OR specific Day Report consequence OR specific business mechanic that teaches this.]
[Include exact dialogue lines, exact UI states, exact events. NOT abstract — concrete.]
[Cross-link to other concepts that compound with this one.]

## Real-world bridge
[How a player applies this concept OUTSIDE the game. What's a real-world challenge they could attempt this week?]

## Pedagogy notes (for the design team)
[How this concept interacts with the eight rules in 07-pedagogy-design-rules.md.]
[Specifically — what's the "stealth" angle? How does the player feel like a founder, not a student?]

## Open questions for human review
[1-3 questions the human should answer before this deep-dive is locked.]

## Sources
[Markdown bullet list with links.]
```

### Step 4 — Open a GitHub issue

Create an issue in this repo titled: `[curriculum-review] {concept name} — {date}`. Body:

```markdown
The curriculum agent drafted a new concept deep-dive today.

**Concept:** {name}
**Pillar:** {1-8}
**File:** [curriculum/concepts/{slug}.md](link to file)

**Open questions for you:**
1. {question 1 from the deep-dive}
2. {question 2}
3. {question 3}

**To approve:** edit the markdown if needed, change `status: draft` to `status: approved`, close the issue.
**To request a rewrite:** comment with feedback, leave status as `draft`, the agent will revisit on its next fire.
**To skip:** close the issue with comment "skip" — concept marked as deferred.
```

Add labels: `curriculum-review`, `pillar-{N}`, `agent-output`.

### Step 5 — Commit + push

Single commit per fire:

```
docs(curriculum): {concept name} deep-dive [agent]

Pillar: {N}
Status: draft
Issue: #{issue number}

Generated by NextOps Curriculum Agent run {run-id}.
```

Push to `main`. The agent never opens PRs — direct push to main is fine because every change is a `draft`-status markdown file gated by a tracking issue.

## What the agent NEVER does

- Auto-merges or auto-approves anything (even its own output).
- Modifies game code repos (`nextops-ekasi-loadshedding`, `nextops-founder-mode-roblox`, etc.). Curriculum-only.
- Touches files outside `curriculum/concepts/` and the issue tracker.
- Repeats a concept that already has `status: approved`.
- Sends real-world communications (no Slack, no email, no Tweet).
- Makes claims it cannot cite. Unsourced claims are flagged or cut.

## Coverage tracker

The agent maintains `curriculum/concepts/INDEX.md` with a table:

| Concept | Pillar | Status | First-drafted | Last-revisited | Issue |
|---|---|---|---|---|---|
| customer-discovery | 3 | approved | 2026-04-30 | — | #4 |
| ... | | | | | |

This is the single-page view of curriculum coverage.

## When the human runs out of bandwidth

If the issue queue grows past 10 unresolved `curriculum-review` issues, the agent's next fire pauses new concept drafts and instead:
- Comments on each open issue with a TL;DR + a recommended close action.
- Reduces output to 1 maintenance issue per day until the human catches up.

This prevents drowning the human in unread agent output.

## Manual override

The human can pause the agent any time via:

1. Going to the routine URL on claude.ai/code/routines and disabling.
2. Or commenting `pause-agent` on any open `curriculum-review` issue. The next fire reads recent issues and self-pauses if it sees this directive.

Resume by enabling the routine again.

## Versioning

When 00-overview.md is materially updated (new pillar added, sub-concept added), the human comments `index-stale` on the latest issue. The agent's next fire updates INDEX.md and re-prioritizes the queue.
