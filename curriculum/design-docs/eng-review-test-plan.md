## Affected Pages/Routes (Roblox places)
Single Roblox place (one universe, one place ID). All flows happen inside this place.

## Key Interactions to Verify

### Onboarding (first session)
- Player spawns → Gogo tutorial NPC appears → claim plot in starter district
- Build mode: place wall, place shelf, place fridge — drag-place + pinch-rotate on mobile
- Open wholesaler menu → buy first stock (constrained to 3 product slots)
- First customer NPC walks in with want bubble → click NPC → dialogue tree → match product → sale completes
- End of in-game day → Day Report panel fires (3-day-ago history visible by day 3)

### Customer discovery (Mom Test pedagogy)
- Talk-to-NPC-first path: NPC reveals specific past-behavior preference → player stocks correctly → 3x revenue compared to guess-stocking
- Generic dialogue option always yields generic answer ("I dunno, what you got?")
- Specific past-behavior question always yields useful answer ("I bought bread Tuesday and Friday last week")
- Repeat customer NPC remembers past purchase across sessions (loyalty record persists)

### Game Pass purchase (VIP Spaza, 199 Robux)
- Click in-game prompt → MarketplaceService.PromptGamePassPurchase fires
- Robux flow completes → callback fires → entitlement persists in ProfileService
- Player rejoins different server → entitlement still active (verify via UserOwnsGamePassAsync cache + persisted flag)
- Premium subscriber: passive Robux ticks via PolicyService check + PremiumPayouts API

### Developer Product purchase (Kasi Cash packs)
- Click 50/200/500 Robux pack → PromptProductPurchase
- ProcessReceipt callback fires → grant in-game R-currency → return PurchaseGranted
- Idempotency: simulate transient DataStore failure on grant → ProcessReceipt returns NotProcessedYet → Roblox retries → second call grants exactly once (NOT twice)

### Stokvel (single-player NPC, v1)
- Meet 9 NPC members in starter district → opt-in to stokvel
- Monthly contribution auto-deducts from capital each in-game month (24 min real-time per game-day, ~12 hours real-time per game-month)
- Each game-month, fixed-rotation member receives payout
- Player crashes mid-month → rejoins → rotation index unchanged, contribution count intact
- Skip-a-month: insufficient capital at deduction time → defaulted contribution → reputation penalty visible in district

### Shared multiplayer district (1.1B)
- Two players' spazas in same district → NPC customer pool shared
- Player A drops bread price R1 below player B → district loyalty shifts toward A → B sees revenue drop in next Day Report
- Player A spam-changes price 100x in 1 second → AntiExploit rate-limits, only first 10 commits, no oscillation damage
- Visible: see neighbor player's empire size, leaderboards, status icons

### Random events (3 hand-tuned, v1)
- Load shedding fires randomly → all fridges go offline 2 in-game hours → perishable stock spoils unless inverter Game Pass active
- Taxi strike fires → walk-in customer count drops to ~10% for 1 in-game day → player adapts (sell off perishables, run promotions)
- Gogo's funeral fires → catering demand spike → snacks/cooldrink stock sells out 5x normal rate

### Day Report (build-measure-learn)
- End of in-game day → Report panel slides in from side (NOT modal — modals get instantly dismissed)
- Shows: products sold, products NOT sold, customer requests you didn't have, top-3 unmet wants
- 7-day rolling history accessible via "Yesterday / Last Week" tabs
- Player taps a row → district preference detail visible

### Save / load lifecycle
- First save fires at 90s autosave OR PlayerRemoving (whichever first)
- BindToClose: 50 players, all profiles released in parallel within 30s window
- Schema migration: profile loaded with schema_version=1 → upgraded to v2 on next save (no data loss)
- DataStore outage: 5 retries with backoff → graceful "save failed, retry in 60s" UI, NO silent data loss

### Mobile UI (1.3A)
- All UI panels render correctly on 360x720 (mid-tier Android)
- Touch targets ≥ 44px per Roblox accessibility guideline
- Build mode gestures (drag-place, pinch-rotate) work without keyboard
- Day Report readable without horizontal scroll on phone

### Localization (2.1A)
- All UI strings registered with LocalizationService → GetTranslator()
- Default locale en-ZA (English, South Africa)
- Missing-string fallback returns en-ZA, never raw key
- isiZulu translation table (v1.5 stretch) loads cleanly via second translator

## Edge Cases

- Player joins, Roblox kicks them within 5 seconds (network) → ProfileService :Release runs cleanly, no orphan session lock
- Player has 0 Robux but tries to open Game Pass prompt → Roblox shows native Robux purchase flow → returns to game without grant
- Player extends credit ("slate") to NPC who never returns → "money owed" balance grows but never collected → Day Report flags this as cash-flow problem
- District saturation: 4th player opens spaza in same district → arrival rate per shop drops 25% → competitive feedback visible in Day Report
- Two browser tabs / two devices same account → ProfileService session lock blocks second join with clear error
- Inventory bounds: try to stock 10,000 of one item with insufficient shelf space → server rejects, client UI clamps to max
- Stokvel: insufficient capital on contribution day for 2 consecutive months → auto-removed from stokvel with clear notification

## Critical Paths (must work end-to-end)

1. **First-purchase flow:** spawn → tutorial → first stock → first customer → first sale → first Day Report → still alive on day 2 = retention proven
2. **Game Pass real-money flow:** prompt → Robux → callback → entitlement persists → durable across rejoin
3. **Anti-exploit defense:** malformed RemoteEvent payload → server rejects, no economy damage; rapid-fire spam → rate limit kicks in
4. **Save integrity:** any crash, any disconnect, any server shutdown → next session shows same state, no data loss
5. **Stokvel rotation integrity:** mid-month crash → rejoin → no double-payout, no skipped contribution, no broken rotation

## LLM/Eval Tests
None. Founder Mode v1 does not call any LLM at runtime. NPC dialogue is pre-written tagged dialogue tables. If v1.5 adds dynamic NPC dialogue via HttpService → external LLM API, that becomes the first eval-required test (prompt → output quality + content moderation).

## Roblox-specific test infrastructure

- **TestEZ** for unit tests on pure-Lua modules (Economy, AntiExploit, Stokvel, DayNightCycle, save schema migration)
- **Roblox Studio Play Solo + scripted scenarios** for integration (NPC arrival, Day Report fire, Game Pass simulated grant)
- **Roblox Studio multi-client Play (Local Server + 2-4 clients)** for E2E (shared district, anti-exploit rate limit, save/load across sessions)
- **Manual mid-tier-Android playtest** mandatory before each v1 milestone (no automation here, but documented test scripts)

No external CI runner. Roblox Studio is the test bench.
